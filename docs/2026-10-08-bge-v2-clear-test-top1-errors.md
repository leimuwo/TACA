## 主要原因和可核查样例

1. **同一任务中相邻步骤或支持步骤竞争**。例如 Intent 要创建 `scripts/build_briefing.py`，首位却是之后运行该脚本的 `exec`；Intent 要创建 `phase_log.md`，首位却是之后检查该文件的 `exec`。相似目标让向量靠近，模型仍需区分“创建、运行、检查”。同一轨迹其他 step 占失败样例的 250 条，但其中也含同义重试，不能都算模型错误。
2. **`exec` 命令的动作语义或参数没有分清**。232/383 失败的已知正例是 `exec`。例如要 `ls` 检查目录，首位是 `mkdir`；要用 `-L` 请求某 API，首位是另一个站点的 `curl -sL`；要搜索某主题，首位抓到同一项目的其他网页。工具名相同或主题相关，不代表目标和命令效果相同。
3. **明确文件路径、格式、写入内容仍会错排**。`write` 失败 92 条，其中 61 条首位仍是 `write`。例：要求写 `output/README.md`，却把其他文档排第一；要求写 `data/search_log.jsonl`，却排 `output/search_log.md`。同一路径的不同内容也会竞争，例如同一 `weekly_agenda.csv` 有不同日期安排。
4. **标注只认 Action ID，存在确定的假失败**。14 条首位 Action 文本与某已知正例完全相同，只是 ID 不同。按 Action 文本等价重算，Top-1 至少为 435/804 = 54.10%，而当前 ID 指标是 421/804 = 52.36%。另有 9 条同工具同目标但其他参数/内容不同，须逐条判定；例如同一脚本不同 edit 片段可都是正确流程的组成部分，不能自动合并。
5. **部分 GQQ“清晰”筛选仍不充分或原 qrels 可疑**。例如“Create the CSV agenda file”没有文件路径或内容条件，却被标清晰；同路径的两个 agenda 写入均可能符合字面 Intent。还有 Intent 明确要求 `web_fetch`，已知正例却是 `exec curl`，应回查原始匹配标注。前排 Action 是否真正正确，需要人工基于原任务上下文复核。

## 结论

最值得先修的是评测标签按 Action 文本/等价实现去重并人工复核高位未标注候选，再处理 `exec` 的同任务相邻步骤错排和 `write` 的目标/内容错排。此后重新报告明确 Intent 子集的 Gold 或充分审核后的指标。现有结构计数是现象分布，不等于人工确认的根因占比。
